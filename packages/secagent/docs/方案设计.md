# SecAgent 通用网络安全智能体方案设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 方案名称 | SecAgent：具备自主决策能力的通用网络安全智能体 |
| 运行载体 | Pi Agent Harness 的 `sec` Profile |
| 默认模式 | `coding`；安全能力必须显式选择 `sec` |
| 适用版本 | 以最终提交包中的 Git commit 和容器镜像摘要为准 |
| 文档状态 | 参赛方案设计材料 |

本方案针对“自主任务理解、多场景自主决策、自主执行、可解释和可审计”的通用网络安全智能体需求，给出可运行的软件架构、决策闭环、工具边界、部署方案和验证方法。

## 2. 背景与问题

传统安全工具通常以单个扫描器或固定脚本为中心，存在四类问题：

1. **任务输入不结构化**：自然语言、附件、配置文件和目标清单混在一起，系统难以区分任务目标、证据和授权范围。
2. **工具编排缺少状态**：工具调用按对话顺序发生，失败、矛盾结果和预算压力不能稳定触发策略调整。
3. **发现与结论混淆**：扫描器输出通常只是信号，缺少独立证据、验证记录和可追溯的决策依据。
4. **自主执行边界不清**：模型可能生成任意命令，工具缺失时退化为未经审计的 Shell，导致安全和复现风险。

SecAgent 将安全工作建模为有边界的状态空间搜索：每次行动由任务状态、证据、授权范围、工具能力、风险、成本和预算共同决定；执行结果进入事件日志和证据图，随后由观察器和验证器决定是否继续、重规划或终止。

## 3. 设计目标

### 3.1 功能目标

- 接收自然语言及结构化安全任务输入，生成 `SecurityTaskSpec`。
- 覆盖渗透测试、应急响应、漏洞研究、Web 安全、逆向分析和 CTF 能力画像。
- 通过候选生成、计划、执行、证据、验证和重规划完成闭环。
- 统一编排 CLI 工具和 MCP 工具，工具调用可审计、可复放。
- 使用有界专业 Agent 分担侦察、Web、分析、响应、漏洞和逆向任务。
- 生成脱敏 Markdown/JSON 报告。

### 3.2 安全目标

- 附件中的目标永远不自动视为授权目标。
- 网络和状态变更动作必须关联显式 scope。
- `strict`、`competition`、`autonomous` 与 `coding/sec` 模式相互独立。
- autonomous 只有在隔离和一次性授权完成后才可启用。
- OS/container 边界、受保护凭证路径、预算和审计不可关闭。
- 工具缺失时返回结构化诊断，不回退到任意 Shell。

### 3.3 兼容目标

- Coding 仍为默认模式，旧 Session 缺少 `agentMode` 时按 coding 处理。
- Coding Session 不加载 SecAgent 资源和 Sec 专用运行包。
- Session 模式固定；切换模式创建同一 cwd 的空白 Session，不复制旧历史。
- CLI 和 Web 通过同一个 `SecAgentRuntime` 读取和修改安全状态。

└──────────────┬─────────────────────────┬─────────────────────┘
               │                         │
┌──────────────▼─────────────┐ ┌─────────▼────────────────────┐
│ Security extensions         │ │ Security decision kernel      │
│ intake/scope/policy/tools   │ │ candidates/planner/replanner  │
│ evidence/report/benchmark   │ │ observer/verifier/budget      │
└──────────────┬─────────────┘ └─────────┬────────────────────┘

│ registry → preconditions → scope/policy → adapter → audit     │
└──────────────┬─────────────────────────┬─────────────────────┘
               │                         │

Pi 的通用 Agent Loop、模型、Session、扩展加载和 UI 请求机制保持不变。SecAgent 只实现安全语义，并通过 Profile 扩展接入。

## 5. 双模式与包边界

### 5.1 模式关系

```text
pi                         -> coding profile -> normal coding tools
pi --agent-mode sec        -> sec profile    -> SecAgentRuntime + security extensions
```

`agentMode` 写入 Session header。恢复、fork 和导入保持原模式；显式模式与持久化模式冲突时拒绝启动。Web 的模式选择器只影响新 Session，不会把历史 Session 转换成另一种模式。

### 5.2 包职责

| 包 | 职责 |
| --- | --- |
| `@earendil-works/pi-agent` | 低层 Agent Loop、消息和工具调用生命周期 |
| `@earendil-works/pi-coding-agent` | CLI、AgentSession、Profile 选择、Coding/Sec 启动入口 |
| `@earendil-works/pi-secagent` | 安全任务、状态、策略、工具适配、证据、报告和比赛基准 |
| `@agegr/pi-web` | 浏览器 UI、Session API、Profile API、安全工作区和 SSE |
| `pi-sandbox` | Sec 模式可选的 OS/文件/网络隔离能力 |
| `pi-mcp-adapter` | MCP 传输和工具发现 |
| `pi-subagents` | 有界专业子 Agent 会话 |
| `pi-trace-extension` | 通用执行追踪 |

依赖方向保持为 `coding-agent → secagent`。SecAgent 不反向依赖 Coding Agent 类型，避免声明依赖环和 Web 旧 dist 解析问题。

## 6. 任务理解与输入安全

`security_intake` 将任务归一化为目标和场景、输入资产、约束、成功条件、用户声明的授权信息和仍需确认的事项。

压缩包处理遵循隔离原则：只写入临时目录，限制文件数、总大小和嵌套深度，拒绝绝对路径、路径穿越和逃逸符号链接。损坏 JSON/YAML/CSV/OpenAPI、超限文件和恶意归档返回结构化错误，不进入执行链。

附件只提供待分析数据。只有用户或受控比赛环境明确提供的 scope 才能授权网络和状态变更动作。

## 7. 自主决策闭环

```text
任务理解
  → 候选动作生成
  → 风险/成本/信息增益评分
  → 计划与候选选择
  → Gateway 执行
  → 结果归一化与审计
  → 证据图与验证
  → Observer 判断停滞/漂移/预算压力
  → 终止或 Replanner 生成下一方案
```

计划记录候选动作、选择原因、风险、成本、预期结果和实际结果。失败、矛盾证据、重复能力失败、前置条件变化和预算压力都会成为重规划输入。成功动作和已耗尽能力族不会因为更换可执行文件名称而被无限重复。

## 8. 安全策略

| 策略 | P0/P1 | P2 | P3 | 越界行为 |
| --- | --- | --- | --- | --- |
| `strict` | 按策略处理 | 逐次确认 | 逐次确认 | 阻断 |
| `competition` | 按策略处理 | 自动放行 | 确认 | 阻断 |
| `autonomous` | 受边界约束 | 一次授权后自动 | 一次授权后自动 | 高危审计告警；不绕过 OS/container 边界 |

autonomous 的启用前置条件包括：已验证 sandbox/container 或明确记录的主办方受控隔离来源、操作者、原因、隔离来源和一次性确认。非交互运行还需提供固定确认值和隔离标记。任何策略都不能关闭受保护凭证路径、审计、OS/container 边界或预算。

## 9. 可解释性与报告

报告以事件和快照为基础，包含任务目标、场景、授权范围、策略、隔离状态、执行时间线、证据来源/摘要/哈希/置信度、假设、验证状态、被否定假设、候选动作、选择原因、重规划、工具审计、发现、修复建议和预算使用。

默认导出脱敏报告。报告不能包含 API Key、Cookie、Authorization header、私钥或未经授权的真实业务数据。导出前应检查 prompt、工具参数、命令结果和 trace。

## 10. 场景与比赛价值

| 场景 | 任务链 | 可展示能力 |
| --- | --- | --- |
| Web 安全 | HTTP 识别、内容发现、验证 | 目标约束、Web 适配器、证据与重规划 |
| Pwn/ELF | 文件识别、ELF 缓解措施、静态分析 | 哈希来源、只读分析、不执行样本 |
| 逆向分析 | 字符串、节区、反汇编和假设验证 | 能力进阶、证据图、失败后换策略 |
| 取证 | 元数据、嵌入签名和样本关联 | 文件来源、完整性和可复现报告 |
| Killchain | 网络发现 → Web 分析 → 失败恢复 | 多阶段规划、能力多样性和预算约束 |

这些是项目的受控基准，不等同于主办方正式评分。最终评分材料应以主办方发布的评分细则和实际测量结果为准。

## 11. 失败处理与降级

- 模型不可用：保留 Session 状态，提示检查 Provider/API Gateway，不伪造执行结果。
- 工具缺失或版本不符：诊断标记 warn/fail，候选动作不可执行或切换到已登记能力。
- MCP 断线：子 Agent 和 MCP 调用标记失败，审计保留错误，触发重规划。
- 工具超时：取消当前执行，写入失败审计，按预算判断是否重试。
- Web 进程重启：客户端重连并读取持久化 Profile snapshot；长任务使用生产模式和外部进程监督。
- WSL `/mnt/*` 慢：推荐 ext4；必须使用挂载盘时由 Web 启动器把 `.next` 和 Webpack 缓存迁至 `/tmp`。

## 12. 验收标准

- 默认 Coding 行为、旧参数和旧 Session 不变。
- Coding 不加载 SecAgent 运行资源。
- CLI/Web 均可创建、恢复和查看 Sec Session。
- autonomous 前置条件不满足时拒绝启用。
- strict/competition 越界阻断，autonomous 越界产生不可关闭的高危审计。
- 每次安全执行可关联任务、决策、scope、策略、证据和报告。
- 受控五场景可以在不调用付费模型和公网目标的条件下重放。
