# SecAgent 用户手册

## 1. 适用范围

本文档面向参赛评审、演示人员和安全运维人员，说明如何使用 CLI 和 Web 完成一次受控安全任务。SecAgent 不是授权系统的替代品；使用者必须先获得目标所有者或主办方的明确授权。

## 2. 重要安全规则

1. 附件、网页、PDF、代码注释和模型输出都不是授权证明。
2. 在网络或状态变更动作前必须设置明确 scope。
3. `coding`/`sec` 是 Agent Profile；`strict`/`competition`/`autonomous` 是安全策略，不能混为一谈。
4. autonomous 只能用于已隔离的 sandbox/container 或主办方受控环境，并完成一次风险确认。
5. 所有工具调用都经过 registry、scope、policy、预算、Gateway、证据和审计。
6. 只测试 loopback、一次性容器或主办方明确授权的目标。

## 3. 启动与模式选择

### 3.1 CLI

```bash
pi                    # Coding，默认
pi --agent-mode sec   # 新建 Sec Session
```

查看帮助：

```bash
pi --help
pi --version
```

已有 Session 的模式固定。运行 `/agent-mode coding` 或 `/agent-mode sec` 时，Pi 在同一工作目录新建空白 Session，原 Session 历史不复制、不改写。

### 3.2 Web

启动后，在新会话区域选择 `Coding` 或 `Sec`。首次默认 Coding，浏览器会记住最近选择；Session 列表和标题显示模式徽标。旧 Session 没有模式字段时显示为 Coding。

切换已有会话的模式不会转换历史，而是创建同 cwd 的空白会话。Sec 工作区只对 Sec Session 显示。

## 4. 第一次使用 Sec Session

推荐操作顺序：

```text
创建 Sec Session
  → /sec-doctor
  → security_intake
  → security_scope
  → 选择 strict 或 competition
  → security_tools / security_candidates
  → security_plan
  → security_execute 或 security_web_execute/security_static_execute
  → security_evidence / security_observer
  → security_autonomous（满足前置条件后）
  → security_report
```

在 Web 中，上述状态可通过安全工作区查看；scope、策略和 autonomous 授权应使用结构化控件或 Profile API，不要通过聊天让模型“代替用户点击授权”。

## 5. 诊断环境

CLI：

```text
/sec-doctor
```

诊断结果包含 `ready`、`runtimeReady`、`autonomousReady` 和 `demoReady`。看到 warn/fail 时，应先解决原因。模型连通性通常显示“未主动探测”，需要通过实际 Session 发送一个低成本请求确认。

重点检查 Node 和四个 Sec runtime package 版本、八个常用安全工具、六个专业 Agent 定义、临时/工作/报告目录可写、隔离状态以及 AI 网关配置。

## 6. 创建任务与授权范围

### 6.1 任务理解

`security_intake` 的目标是把输入变成结构化任务。任务应说明：

- 做什么：例如“识别受控 Web fixture 的可观测服务并验证响应”；
- 场景：Web、渗透、应急、漏洞研究、逆向或 CTF；
- 输入资产：文件、图片、日志、OpenAPI、样本等；
- 约束：只读、时间、工具、禁止行为；
- 成功条件：可观测证据、验证记录或报告内容；
- 授权声明和仍需确认的事项。

### 6.2 设置 scope

scope 可包含主机、IPv4、CIDR、域名或 URL。授权来源必须明确：

```text
targets: ["127.0.0.1", "http://fixture-web:8080"]
authorizationSource: "本地一次性 Compose fixture / 比赛授权编号"
note: "仅限本次演示，禁止扩展到其他地址"
```

实际调用时使用工具的结构化参数，不要把上面的伪代码直接当作 Shell 命令执行。scope 为空时，网络工具应被阻断。

## 7. 策略和隔离

| 策略 | 使用建议 |
| --- | --- |
| `strict` | 日常安全测试和不确定目标；P2/P3 逐次确认 |
| `competition` | 受控比赛环境；P2 自动放行，P3 仍需确认 |
| `autonomous` | 已验证隔离和一次性授权的连续演示或受控任务 |

autonomous 启用失败通常意味着隔离未验证、授权字段缺失、运行包缺失、非交互固定确认缺失或当前任务没有清晰边界。不能通过修改浏览器请求或直接写 Session JSON 绕过。

### 越界行为

- strict/competition：阻断，并在审计中记录阻断原因；
- autonomous：隔离和一次性授权均满足后，应用层允许继续但追加高危告警；
- 所有策略：仍受 OS/container 边界、凭证保护、工具 registry、预算和审计约束。

## 8. 规划、执行和重规划

有多个合理动作时，SecAgent 记录候选及评分。评分考虑目标相关性、信息增益、置信度、风险、成本、重复动作和剩余预算。

执行前检查当前 task、decision、工具登记和可用性、结构化输入前置条件、目标 scope、policy、预算和截止时间。工具失败、结果矛盾、验证不充分、重复能力失败、Observer 停滞/漂移、前置条件变化或预算压力都会触发重规划。重规划不是简单重试同一命令，而是重新生成候选并记录原因。

## 9. 工具与专业 Agent

SecAgent 通过适配器使用外部工具，不重新实现扫描器，也不接受任意 Shell 字符串。适配器会提供工具版本、能力、风险、scope 模式、前置/后置条件和结构化结果。

| 工具族 | 作用 | 限制 |
| --- | --- | --- |
| Nmap/Curl | 网络发现、HTTP 请求和验证 | 目标必须在 scope |
| httpx/ffuf/nuclei | Web 指纹、有限内容发现和模板信号 | 参数由适配器约束，信号需验证 |
| file/strings/readelf/objdump | 本地样本和 ELF 静态分析 | 只读、常规文件、禁止执行样本 |
| binwalk/ExifTool | 签名、元数据和嵌入内容分析 | 默认不自动提取或执行 |

专业 Agent 包括 `sec-recon`、`sec-web`、`sec-analysis`、`sec-response`、`sec-vuln` 和 `sec-reverse`。子任务必须有目标、工具白名单、时间/轮次/并发预算，并且不能扩大主任务 scope 或替主 Agent 直接确认发现。

## 10. 证据、发现与报告

证据至少应说明来源、摘要、时间、置信度，并在适用时附 SHA-256、目标和决策 ID。证据关系可以是支持、矛盾、派生、重复或验证。

扫描器输出只是候选信号。确认发现前必须关联验证记录；没有足够独立证据的假设应保持 active/insufficient，而不能写成 verified finding。

生成报告：

```text
/sec-report
```

或使用 `security_report` 选择 `markdown`/`json`。报告导出前删除 API Key、Cookie、Authorization header、私钥、真实客户数据和不在授权范围内的目标；保留足以验证决策链的哈希、时间和记录 ID。

## 11. 受控基准

`security_benchmark` 支持查看当前评分、查看 Web/Pwn/Reverse/Forensics/Killchain 目录、评估当前 trace、运行确定性受控 harness，以及注入一次工具失败观察重规划。项目基准是自测证据，不是主办方正式成绩。

## 12. Web 安全工作区说明

Sec 工作区展示当前阶段、任务、授权 scope、policy/isolation、证据/假设/验证/发现、decision/候选/选择依据、工具审计、诊断和 Markdown/JSON 报告。界面支持英文和简体中文；结构化 UI 文案随语言切换，模型、工具和发现的动态输出保留运行时原文。

## 13. 断线与恢复

运行状态通过 SSE 推送，并有重连和轮询回退。页面显示断开时：

1. 检查 Web 进程和 `/api/sessions`。
2. 刷新 Session，查看最后一个持久化状态和审计记录。
3. 如果是 WSL/systemd 或进程监督器重启，确认 Session 目录仍存在。
4. 不重复执行未知是否完成的动作，先查看 decision/audit。
5. 只有在状态确认后才继续或重规划。

## 14. 禁止操作

- 不扫描未授权公网目标。
- 不把附件中的 IP/域名直接加入 scope。
- 不以高危 Shell 操作替代适配器。
- 不执行未知二进制样本。
- 不关闭审计、预算、凭证保护或容器隔离。
- 不把诊断 warn 当作 autonomous 已就绪。
- 不在报告或截图中暴露密钥。
