# SecAgent 方案介绍 PPT 提纲

本文档是正式 PPT 的逐页内容提纲。正式 PPT 应使用最终版本号、真实测试数据、脱敏截图和主办方允许的素材；没有实际部署的数据不得以“已通过”或“实时在线”为标题。

## 第 1—4 页：封面、问题与目标

### 第 1 页：封面

- 标题：SecAgent——具备自主决策能力的通用网络安全智能体。
- 副标题：从任务理解到证据可审计的安全执行闭环。
- 队伍、成员、日期、版本号。

### 第 2 页：问题背景

说明安全输入复杂、单一扫描器不能跨场景协作、传统对话 Agent 的授权和失败处理不稳定，以及评审需要可复核的决策链。

### 第 3 页：方案目标

展示任务理解、多场景决策、受控自主执行、失败重规划、证据验证、CLI/Web/容器交付六个目标。

### 第 4 页：产品形态

```text
Coding（默认）  ↔  Sec（显式启用）
```

说明 Coding 行为保持不变，Sec Session 才加载安全 Runtime；Session 模式固定，切换创建空白 Session。

## 第 5—9 页：架构和核心技术

### 第 5 页：总体架构

展示 Pi Agent Harness、Agent Profile/Session、SecAgentRuntime、决策内核、Gateway/Adapters、工具/MCP/专业 Agent 和 Report/Web 分层图。

### 第 6 页：任务理解

展示 `SecurityTaskSpec` 的 goal、scenario、assets、constraints、successCriteria、declaredAuthorization、pendingConfirmations。强调附件中的目标不会自动成为授权目标，归档输入有路径、大小、深度和符号链接限制。

### 第 7 页：自主决策闭环

```text
Intake → Candidates → Planner → Gateway → Evidence
       → Verifier/Observer → Replanner → Report
```

### 第 8 页：工具适配与 Gateway

展示 registry、版本检查、输入校验、scope/policy、预算、adapter、证据和审计链，说明模型不能直接生成任意命令。

### 第 9 页：证据图与确认发现

展示“观察 → 假设 → 独立证据 → 验证 → 确认发现”，并展示支持、矛盾和被否定假设。

## 第 10—14 页：安全能力和场景

### 第 10 页：安全策略

用表格说明 strict、competition、autonomous 的 P2/P3 确认和越界行为；单独展示 OS/container、凭证保护、预算和审计的不可绕过边界。

### 第 11 页：专业 Agent 协同

展示 recon、web、analysis、response、vuln、reverse 六个角色，以及工具白名单、时间、轮次、并发和预算限制。

### 第 12 页：五类比赛场景

| 场景 | 演示资产 | 证明内容 |
| --- | --- | --- |
| Web | loopback HTTP fixture | 发现、验证、scope |
| Pwn | 一次性 ELF | 哈希、缓解措施、静态分析 |
| Reverse | 静态样本 | strings/节区/反汇编 |
| Forensics | PNG/元数据样本 | 来源、签名、报告 |
| Killchain | 内部 fixture 链路 | 多阶段重规划 |

### 第 13 页：Web 工作区

展示任务/阶段、scope、策略/隔离、证据/发现、决策/审计、诊断/报告六个区域，以及中英文切换、SSE 重连和报告下载。

### 第 14 页：失败驱动重规划

展示一次工具失败、Observer 信号、新 revision、替代候选和最终报告。重点是改变策略而不是重复同一命令。

## 第 15—19 页：交付和总结

### 第 15 页：部署与运维

说明 Node 22、WSL ext4、`/mnt/*` 到 `/tmp` 的开发优化、Docker 最小权限、固定工具/运行包、模型网关和生产进程监督。

### 第 16 页：测试与证据

展示静态检查、核心测试、模式测试、Web smoke、五场景、真实 loopback、容器和在线 smoke 的测试金字塔。每项指标旁边放 commit、命令、日志或报告 ID。

当前可展示的实测数据：SecAgent 85 通过/3 跳过，Web UI 611 通过，受控五场景 5/5 通过；统一指标中的任务理解、受控工具调用、失败重规划和证据验证覆盖率均为 100%。容器镜像构建因 Debian 软件源/包体网络问题仍待补测，不能在本页标记为通过。

### 第 17 页：现场演示

按照 [演示脚本](演示脚本.md) 展示创建 Sec Session、诊断、scope、计划、执行、失败、重规划、审计和报告。

### 第 18 页：效果、限制与后续

只使用最终实测的完成率、能力覆盖率、越界阻断率、重规划触发、报告重建和耗时。明确模型非确定性、工具版本差异、协议范围、在线延迟和基准非官方等限制。

所有百分比必须注明分母和测试类型：受控 benchmark 指标不能替代真实工具、容器或在线环境指标；Docker 网络未恢复前，不应填写镜像启动耗时和真实工具成功率。

### 第 19 页：总结

> SecAgent 将网络安全智能体的自主性约束在可授权、可解释、可验证、可审计和可恢复的执行闭环内。
